# Decision log

| Date | Decision | Alternatives | Reason |
|---|---|---|---|
| 2026-09-10 | Reproduce the authors' BERT recipe *unchanged* (unstratified split, seed 42, no early stopping, threshold 0.5) | stratified split, tuned threshold | Comparability with the reported 0.51/0.36 comes first; improvements are not the contribution |
| 2026-09-10 | Add torch/numpy seeds and run 5 seeds | single run like the notebook | The notebook is unseeded, so a single number is not reproducible; report mean +/- std and a +/-0.02 tolerance |
| 2026-09-10 | Post label = symptoms with status==1; negatives -> NO_SYMPTOMS (10 classes) | drop negatives; 9 classes | Mirrors analysis/statistics.py and the notebook's 10-class head |
| 2026-09-10 | Keep status==0 rows as "rejected candidate" evidence | discard | They are gold examples of topic-match-without-evidence, useful later for the plausibility analysis |
| 2026-09-10 | Test set = 297 posts (sklearn ceils 0.2 * 1484) | - | Recorded so per-symptom support numbers are interpretable |
| 2026-09-25 | TP vs FP contrasts use an unpaired bootstrap and Mann-Whitney, not a paired test | paired bootstrap / Wilcoxon, as first written in the plan | A (post, symptom) pair is either a TP or an FP, never both, so the two groups are disjoint and there is nothing to pair. Paired tests stay for contrasts on the same items: IG vs LIME, plausibility vs faithfulness, M2 vs M3 on the same posts |
| 2026-09-25 | H1 reported as a difference in differences with a bootstrap interval | two separate TP-FP gaps compared by eye | The claim is that the faithfulness gap exceeds the plausibility gap, so it should be one number with one interval rather than an informal comparison of two |
| 2026-09-25 | M3 is Qwen 2.5 7B Instruct, run locally through Ollama | Llama 3.x 8B, gemma-3, an API model | The LREC 2026 comparison of eight open models on these same nine DSM-5 symptoms put Qwen 2.5 7B first and found no gain from 7B to 14B, so it is the best operating point at a size that runs here. Local weights also mean no post ever leaves the machine and the model cannot drift under me |
| 2026-09-25 | Call Ollama with format=json rather than relying on the prompt alone | free-form output plus a parser with retries | Constrained decoding removed parse failures in the probe and cut latency by roughly a third. The retry path stays in the code for the cases it cannot save |
| 2026-09-25 | Sentences split with NLTK Punkt, but each line split separately | one regex of my own; Punkt on the whole post; spaCy | Punkt is the standard and is not something I should re-derive, but it does not end a sentence at a line break. Reddit posts use line breaks instead of full stops, so running it per line stops three separate symptom claims collapsing into one unit of explanation |
| 2026-09-25 | Gold evidence matched to my split by exact, then substring, then word overlap above 0.5, with the failure rate reported | require an exact match; trust sentence_id as an index | Exact matching alone cannot be verified until the real data arrives. Reporting the failure rate by match type makes the choice evidence-based rather than assumed. On the paraphrased sample every gold sentence that did align landed on the index its sentence_id predicted, 5 of 5, which suggests the ids may index the post directly on the real data |
| 2026-09-25 | LIME written rather than taking the `lime` package | lime.lime_text.LimeTextExplainer | The library segments text its own way and assumes a sklearn-style predict_proba. My unit of explanation is the sentence and my M3 is an LLM behind an HTTP call, so the library would have been bent further than it would have been written. Forty lines I can defend line by line, with the perturbation scheme stated explicitly |
| 2026-09-25 | LIME returns the local weighted R-squared alongside the weights | weights only | A low R-squared means a linear surrogate does not describe the neighbourhood, so the weights are not a trustworthy summary. Reporting it keeps that visible instead of assumed |
| 2026-09-25 | The LLM's self-reported confidence is treated as a binary decision signal, not a probability | take the 0-100 value at face value; find graded probabilities elsewhere | A drop-one-sentence probe returned 100 for every perturbation except the one that removed the evidence sentence, which returned 0. Ollama exposes no token log-probabilities, so nothing graded is available. LIME still has signal to fit, and ERASER comprehensiveness on M3 becomes a flip rate, which the plan already allowed for. Recorded in the pre-registration before any real data |
| 2026-09-25 | Every model call is cached on disk, keyed by model, system prompt, prompt and seed | re-query each time | The M3 LIME run is on the order of a day. Caching turns an interrupted run into a resumed one, and a repeat call went from 15s to 3ms in testing |
| 2026-09-25 | A malformed reply is retried with the failure reason appended and the temperature raised; only transport errors retry unchanged | retry identically; vary the seed; raise on first failure | Ollama ignores the seed at temperature 0, verified by probe: three seeds returned byte-identical output. So a retry has to change the prompt or the temperature, and it does both. The first pass stays at temperature 0 and reproducible |
| 2026-09-25 | Training runs on the Apple GPU when CUDA is absent, with the device recorded in every metrics file | CPU only; Colab only | Benchmarked at the real batch of 8 and 512 tokens: 1.38 s/step on the Apple GPU against 5.13 on CPU, so the five-seed run falls from 5.3 hours to 1.4. Nothing in the recipe changes, only where the arithmetic happens, and `device:` in the config forces CPU if the two ever need comparing |
| 2026-09-25 | Figures are generated by a script in the repo, in greyscale, and committed | draw them by hand in a graphics tool | A figure that regenerates from code cannot drift from what the pipeline actually does, and greyscale means it survives a monochrome print of the paper |
| 2026-09-25 | LIME uses 100 perturbations per (post, symptom), not the 200 the plan suggested | 25, 50, 200 | Measured on a 14-sentence post against a synthetic model, comparing each run's top-3 sentences with a 1,000-sample reference over 5 seeds: 25 gave 0.70 Jaccard, 50 gave 0.90, 100 gave 1.00 and 200 gave no further gain. Re-check on real posts, since the count needed rises with sentence count |
| 2026-09-25 | M3 LIME will be run with parallel Ollama requests, and the cost is budgeted up front | run it single-threaded | At 2.9s per label-only call, 297 test posts at 100 perturbations is about 24 hours single-threaded. Raising OLLAMA_NUM_PARALLEL brings it to roughly six. The disk cache makes an interrupted run resumable either way |
| 2026-09-25 | Plausibility is measured against the same symptom's gold rationales from the training split, identically for correct and incorrect predictions (prereg amendment 1) | own-post G_text as first written; the status==0 rejection note; own-post for TPs and other posts for FPs | On a false positive the post has no gold rationale for that symptom, so the primary statistic could not be computed. Using other posts for both groups keeps one measuring stick; mixing own-post and other-post references builds a gap into the measure. Own-post similarity stays as a secondary on TPs, the 0.78 comparison |
| 2026-09-25 | Mean similarity over the reference set, and a null baseline against the other eight symptoms' references | max similarity; null against one random post's rationale for the same symptom | The mean is less driven by one lucky near-duplicate than the max. Once every item is compared with other posts, a same-symptom null would be the measure itself, so the useful null is whether a rationale sits closer to its own symptom than to the others |
| 2026-09-25 | G_text for a (post, symptom) is its evidence-sentence explanations joined in sentence order | average the per-sentence embeddings | One text, one embedding, compared the same way as the model's single rationale |
| 2026-09-25 | Bootstrap resamples posts, not (post, symptom) items | item-level resampling, as implemented | The prereg already said posts. Items from one post are correlated: a synthetic check with 2 correlated items per post gave an item-level interval 27% narrower than the post-level one |
| 2026-09-25 | Erasure and LIME on M3 use the joint prompt, not the label-only prompt | label-only prompt, which is about 2.5 times faster | The two prompts gave different label sets on 5 of 17 sample posts at temperature 0, so the label-only prompt measures a different decision from the one S explains. M3 LIME goes from about 6 to about 15 hours with parallel requests; the cache makes it resumable |
| 2026-09-25 | A-vs-S overlap uses k = \|S_evid\|; k = \|G_evid\| only for A-vs-G on correct predictions | k = \|G_evid\| throughout, as first written | \|G_evid\| is 0 on every false positive, which would score A-vs-S overlap 0 on every incorrect prediction by construction and manufacture the H1 result |
| 2026-09-25 | Rationales are embedded with nomic-embed-text and no task prefix | "clustering: ", "classification: ", "search_document: " | nomic-embed-text was trained with task prefixes and Ollama adds none, so this is a real choice. On the sample's 21 gold rationales, the gap between same-symptom and other-symptom mean cosine was 0.125 with no prefix against 0.093, 0.112 and 0.077 with the prefixes. Only 21 paraphrased texts, so re-check on the real data before any number is reported. The same probe put other-symptom rationales at 0.69 cosine with each other, which is why the null baseline matters next to ReDSM5's 0.78 |
| 2026-09-25 | Integrated Gradients written by hand over the word embeddings, not taken from Captum | captum.attr.LayerIntegratedGradients, as the plan said | Same reason as LIME: about twenty lines I can defend, with the path, baseline and step rule stated in the code. Captum 0.9.0 would have installed fine, so this is not a compatibility workaround. Cross-checked against Captum's LayerIntegratedGradients on the word-embedding layer of a small BERT with non-trivial weights: per-token attributions agreed to 7e-7 on attributions up to 1.9, with the same completeness gap at 20 and 300 steps |
| 2026-09-25 | The IG baseline is [PAD] at every position except [CLS] and [SEP]; [UNK] is not kept | all-[PAD] including the specials; all-[MASK] | Keeping [CLS] and [SEP] means only the words move along the path, so the specials get exactly zero attribution and cannot crowd out sentences. [UNK] stands for a real word in the post, so it moves like any other. Position and segment embeddings are identical in input and baseline, so they carry no attribution |
| 2026-09-25 | IG runs 50 midpoint steps in batches of 10 | 100 steps; batches of 25 | On full-size bert-base at 512 tokens on the Apple GPU: 6.3s per (post, symptom) at batch 10, about 47 minutes for the test set, with a completeness gap of 3e-3 on an untrained head. Batch 25 took 92s, because 16 GB cannot hold 25 copies of the activations and the GPU stalls. The gap is reported per item, so steps can be raised where it is large |
| 2026-09-25 | Negative affect is counted with the NRC Emotion Lexicon's fear, anger and sadness words | LIWC negemo (paid); NRC 'negative'; VADER; the Hu and Liu opinion lexicon | The literature this checks against (Rude et al. 2004) used LIWC negative emotion, which is anxiety + anger + sadness; these are the matching NRC emotions. NRC 'negative' is sentiment polarity, VADER is sentiment, and Hu and Liu is product-review opinion, so none of them is an emotion measure. NRC is licensed for research: downloaded by hand, read from data/, gitignored |
| 2026-09-25 | Markers are rates per word; present tense is the share of finite verbs (VBP, VBZ against VBD) | raw counts; present-tense verbs per word | Rates let a short attributed sentence be compared with a long unattributed one, which is what the marker-density check does. Tense only shows on finite verbs, so dividing by all words would mix tense with how verb-heavy the text is. nan where there is nothing to divide by, left for the caller to handle |
| 2026-09-25 | Absolutist words are the 19-word dictionary of Al-Mosaiwi and Johnstone (2018) | a longer list of my own | It was validated on mental-health forum text, which is close to Reddit. The list in src/lexicon.py was written from memory of the paper: check it against the paper's table before any result is reported |
| 2026-09-25 | M1 is one L2 logistic regression per label (C = 1) on TF-IDF 1-2 grams with min_df 2, plus the four markers standardised on the training posts | sklearn OneVsRestClassifier; tuned C; an associative classifier | One regression per label is what one-vs-rest is, written so every head's weights are in reach and a label that never varies in training gets a constant instead of a crash. C is left at the default because there is no validation split to tune it on without changing the reproduction. Markers are standardised so their weights are on a scale comparable with each other; a missing marker becomes the training mean |
| 2026-09-25 | TF-IDF keeps one-letter tokens, so "I" is a feature | sklearn's default token pattern, which drops tokens under two characters | The default silently removes "I", the most studied word in depression language, and every bigram containing it ("i cant", "i feel"). Found by a failing test |
| 2026-09-25 | M1's sentence score is the sentence's exact share of the label's logit; markers, boundary-crossing bigrams and the bias are reported separately | sum of the weights of features present in the sentence, as the plan said | A linear logit is a sum of weight * value terms, so each n-gram's term can be split across the sentences it occurs in by occurrence count, and sentences + markers + crossing + bias equals the logit exactly. That is what faithful by construction means, and it is tested as an equality. Summing bare weights would ignore TF-IDF values and double-count repeated n-grams. Markers are post-level rates and cannot be split into sentences, so their contribution is reported rather than spread |
